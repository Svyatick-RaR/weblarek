# Проектная работа «Веб-ларёк»

## Описание проекта

«Веб-ларёк» — учебный проект интернет-магазина товаров для веб-разработчиков. В рамках текущего этапа реализованы модели данных, базовый класс для HTTP-запросов и коммуникационный слой для взаимодействия с сервером.

Проект разрабатывается с использованием архитектурного подхода MVP (Model-View-Presenter). Текущий этап посвящён подготовке моделей и организации работы с данными. Реализация пользовательского интерфейса и взаимодействия с ним в рамках этого этапа не выполняется.

## Установка и запуск

Для установки зависимостей выполните:

```bash
npm install
```

Создайте файл `.env` на основе `.env.example` и укажите адрес API:

```env
VITE_API_ORIGIN=https://larek.ffapi.ru
```

Для запуска проекта в режиме разработки выполните:

```bash
npm run dev
```

## Сборка проекта

Для проверки TypeScript и создания production-сборки выполните:

```bash
npm run build
```

Для локального просмотра production-сборки можно использовать:

```bash
npm run preview
```

## Архитектура приложения

Проект разрабатывается с использованием архитектурного подхода MVP (Model-View-Presenter), который разделяет ответственность между основными частями приложения.

- **Model** — отвечает за хранение данных, изменение состояния и выполнение бизнес-правил.
- **View** — отвечает за отображение информации и взаимодействие с пользователем.
- **Presenter** — связывает модели и представления, обрабатывает события и управляет логикой взаимодействия.

В текущем этапе реализованы модели данных и коммуникационный слой. Логика представления и взаимодействия с пользователем будет разрабатываться на следующих этапах.

Модели не зависят от DOM и не выполняют HTTP-запросы. Получение и отправка данных выполняются через отдельный коммуникационный слой.

## Базовый класс API

### Класс Api

Базовый класс для выполнения HTTP-запросов к серверу.

**Конструктор:**

- `constructor(baseUrl: string, options: RequestInit = {})` — принимает базовый адрес сервера и дополнительные настройки запросов.

**Основные поля:**

- `baseUrl` — базовый адрес сервера.
- `options` — настройки HTTP-запросов.

**Методы:**

- `get(uri)` — выполняет GET-запрос.
- `post(uri, data, method)` — отправляет данные на сервер в формате JSON. Поддерживает методы POST, PUT и DELETE.
- `handleResponse(response)` — обрабатывает ответ сервера: возвращает данные при успешном запросе или отклоняет Promise при ошибке.

## Модели данных

Модели отвечают за хранение и изменение данных приложения. Они предоставляют методы для получения актуального состояния и выполнения операций с данными.

### Класс Products

Отвечает за хранение каталога товаров и выбранного товара.

**Основные поля:**

- `products: IProduct[]` — список товаров.
- `selectedProduct: IProduct | null` — выбранный товар.

**Методы:**

- `setProducts(products)` — сохраняет список товаров.
- `getProducts()` — возвращает список товаров.
- `getProductById(id)` — находит товар по идентификатору.
- `setSelectedProduct(product)` — сохраняет выбранный товар.
- `getSelectedProduct()` — возвращает выбранный товар.

### Класс Basket

Отвечает за хранение товаров в корзине и выполнение операций с ними.

**Основное поле:**

- `items: IProduct[]` — список товаров в корзине.

**Методы:**

- `getItems()` — возвращает список товаров в корзине.
- `addItem(product)` — добавляет переданный товар в корзину.
- `removeItem(id)` — удаляет товар по идентификатору.
- `clear()` — очищает корзину.
- `getTotal()` — рассчитывает общую стоимость товаров.
- `getCount()` — возвращает количество товаров.
- `hasItem(id)` — проверяет наличие товара по идентификатору.

Метод `addItem()` выполняет только добавление товара. Проверка необходимости добавления выполняется на уровне презентера, а не модели.

### Класс Buyer

Отвечает за хранение и проверку данных покупателя.

**Основное поле:**

- `buyer: IBuyer` — данные покупателя: способ оплаты, email, телефон и адрес.

**Методы:**

- `setBuyer(data)` — частично обновляет данные покупателя.
- `getBuyer()` — возвращает данные покупателя.
- `clear()` — сбрасывает данные покупателя к начальным значениям.
- `validate()` — проверяет заполненность обязательных полей и возвращает объект с ошибками.

При создании экземпляра модели и после вызова `clear()` все поля покупателя пустые. Способ оплаты считается невыбранным до получения соответствующего значения.

## Взаимодействие с API

### Класс ApiClient

Коммуникационный класс, обеспечивающий взаимодействие приложения с сервером. Использует базовый класс `Api`.

**Конструктор:**

- `constructor(api: IApi)` — принимает экземпляр API-клиента.

**Методы:**

- `getProducts()` — получает каталог товаров с сервера посредством GET-запроса на `/product/`.
- `createOrder(order)` — отправляет данные заказа на сервер посредством POST-запроса на `/order`.

Класс `ApiClient` отделяет работу с сервером от моделей данных.

### Настройка API

Адрес сервера задаётся через переменную окружения `VITE_API_ORIGIN` в файле `.env`.

```env
VITE_API_ORIGIN=https://larek.ffapi.ru
```

В файле `src/utils/constants.ts` формируется базовый адрес API:

```ts
export const API_URL = `${import.meta.env.VITE_API_ORIGIN}/api/weblarek`;
```

## Типы данных

В файле `src/types/index.ts` определены основные типы и интерфейсы приложения:

- `IProduct` — структура товара: идентификатор, описание, изображение, название, категория и цена.
- `IBuyer` — структура данных покупателя.
- `TPayment` — тип способа оплаты: `'card' | 'cash' | ''`. Пустая строка означает, что способ оплаты не выбран.
- `IProductsResponse` — структура ответа сервера с каталогом товаров.
- `IOrderRequest` — структура данных для отправки заказа.
- `IOrderResponse` — структура ответа сервера после оформления заказа.
- `IApi` — интерфейс базового API-клиента.

## Тестовые данные

В файле `src/utils/data.ts` находятся тестовые данные товаров, экспортируемые через объект `apiProducts`.

Массив `apiProducts.items` используется для проверки работы моделей на примере заранее подготовленных товаров.

## Точка входа приложения

В файле `src/main.ts` создаются экземпляры моделей `Products`, `Basket` и `Buyer`, а также коммуникационного класса `ApiClient`.

В точке входа выполняются:

- Проверка основных методов моделей.
- Проверка добавления и удаления товаров из корзины.
- Проверка заполнения и валидации данных покупателя.
- Создание API-клиента.
- Получение каталога товаров с сервера.
- Сохранение полученного каталога в модели `Products`.

Получение каталога выполняется асинхронно. При успешном запросе данные сохраняются в модели, при ошибке информация выводится в консоль.
